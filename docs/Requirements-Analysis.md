# Requirements Analysis

## Источник требований
Отдельного технического задания (SRS) для DemoBlaze нет. Требования сформированы на основе изучения интерфейса сайта, прохождения основных пользовательских сценариев и наблюдений за поведением системы.

## Основные предположения
- Сайт предназначен для демонстрации e-commerce сценариев и может работать нестабильно.
- Часть действий доступна без авторизации.
- При ошибках в формах сайт показывает alert-сообщения пользователю.
- Данные корзины и заказов могут не сохраняться между сессиями.

## Функциональные требования

### Аутентификация
- Пользователь может зарегистрироваться (Sign up) с username и password.
- Пользователь может войти в систему (Log in) с корректными учетными данными.
- При входе с несуществующим пользователем вход не выполняется, отображается сообщение об ошибке (например, `User does not exist.`).
- При неверных учетных данных вход не выполняется.
- После успешного входа элемент `Log in` в навигации заменяется на `Log out`.
- Пользователь может выйти из аккаунта через `Log out`.

### Каталог и навигация
- Пользователь может просматривать категории товаров: Phones, Laptops, Monitors.
- Пользователь может открыть страницу товара из каталога.
- На странице товара отображаются название, цена, описание, изображение и кнопка `Add to cart`.
- Пользователь может переходить между разделами сайта через навигационное меню.

### Корзина
- Пользователь может добавить товар в корзину без авторизации.
- Пользователь может добавить один и тот же товар несколько раз.
- Пользователь может открыть корзину и просмотреть добавленные товары.
- Пользователь может удалить товар из корзины.
- Сумма в корзине соответствует добавленным товарам.

### Оформление заказа
- Пользователь может оформить заказ (Place order) без авторизации.
- Для оформления заказа необходимо заполнить форму с данными покупателя.
- После успешного оформления заказа отображается подтверждающее сообщение.
- При незаполненных обязательных полях заказ не оформляется.

### Дополнительные разделы
- Пользователь может открыть страницу `Contact`.
- Пользователь может открыть страницу `About us`.
- Пользователь может отправить сообщение через форму Contact.

## Нефункциональные требования
- Основные страницы сайта открываются без критических UI-ошибок.
- Кнопки, ссылки и формы доступны для взаимодействия в desktop-браузере.
- Действия пользователя сопровождаются обратной связью (alert, сообщения, изменение состояния страницы).
- Текст ошибок понятен пользователю.
- Интерфейс читаемый и удобный для базового функционального тестирования.

## Наблюдения по результатам анализа
- После авторизации пункт `Log in` заменяется на `Log out` (ожидаемое поведение).
- Логин с несуществующим пользователем сопровождается сообщением `User does not exist.`.
- При неуспешном логине API-запрос может возвращать `200 OK`, при этом в UI отображается ошибка (возможная особенность реализации API).
- Добавление товара в корзину сопровождается alert-сообщением.
- Один и тот же товар можно добавить в корзину несколько раз.
- Оформление заказа доступно через модальное окно `Place order`.

## Возможные риски
- Demo-сайт может работать нестабильно.
- Данные корзины и заказов могут сбрасываться.
- Поведение alert-сообщений может отличаться в разных браузерах.
- Валидация полей может быть неполной.

## Результат анализа
На основе проведенного анализа подготовлены основные требования для дальнейшей работы:
- тест-кейсы по UI
- чек-листы
- баг-репорты
- базовые API-проверки в Postman
